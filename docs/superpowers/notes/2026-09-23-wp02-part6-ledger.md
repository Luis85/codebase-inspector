### Design rulings from drafting and reconciliation

| # | Ruling | Cost if wrong |
|---|---|---|
| U8 | **The fallow raw schema uses `z.object` (strip), not `z.looseObject`.** The Global Constraint is amended. With zod 4.6.5, `z.looseObject` keeps undeclared keys in the parse output, so `fragment` (source text), `actions` and `_meta` would survive into memory, breaking "source content is never stored" (Y23). `z.object` tolerates additive fields exactly as well, and drops them. | Low. A future fallow field we want must be declared, which is the intended discipline anyway. |
| U9 | **All fallow code lives in `src/application/evidence/`**: `raw-fallow.ts`, `fallow-report-schema.ts`, `read-fallow-report.ts`, `model.ts`, `normalize-fallow.ts` and `resolve-findings.ts`. There is no `src/adapters/fallow/`. Nothing in `src/application` imports `src/adapters`. The UI's dialog therefore reaches the reader through the existing ui → application edge, and no ui → adapters edge is created. The reader uses only zod and `Blob.text()`, with no Node API. | Low. Part 7's runner is a genuine adapter (process I/O) and will live in `src/adapters/`, producing the same `RawFallowReport` type. |
| U10 | `NormalizedEvidence.notShown` is `{ key, count }`. The UI labels it with `fallowNotShownLabel(key)`, which uses own keys only and falls back to the raw key. It never returns an `Object.prototype` member. Application code holds no UI copy. | None. |
| U11 | Finding ids are `CX-`/`DU-`/`UN-` followed by `fnv1a32Hex` of a stable key (Y24), from a new `src/domain/hash.ts`. The three existing private fnv copies are left alone. **Duplication ids change on a fallow upgrade**, because clone fingerprints differ between 3.21.0 and 3.27.0, so a disposition on a duplication finding does not re-attach across an upgrade. Complexity and unused-export ids are stable. | Low. A reviewer re-decides duplication findings after upgrading fallow. Keying on instance ranges instead would break on any edit. |
| U12 | The normaliser is **snapshot-independent**. `resolveFindings` matches paths against a snapshot separately, so the evidence index re-resolves the same report against a newer snapshot (stale, Y30). | None. |
| U13 | `source-mismatch` is decided in the UI after resolving, with the offered mapping tried first. The COPY-17 wording is adapted, because a fallow report has no source revision: "…none of its findings names a file in the current snapshot, even with the offered folder mapping. Nothing was imported." | Low. |
| U14 | The fixture project has **five** `.ts` files plus `package.json` (the spec is corrected). It is excluded from `tsconfig.test.json`, eslint and oxlint. The controller records the raw outputs **before** Task 5 is dispatched, in Git Bash (PowerShell 5.1's `>` writes UTF-16), from the npx-cached 3.27.0 and 3.21.0 binaries, with no download. Values hard-coded from the dry run are checked by a node script before the commit. | Low. If a recording differs from the dry run, the check fails before anything is committed, and the plan's asserted values are corrected in the ledger. |
| U15 | The review port has **13 members**: the 9 existing ones plus `allocateId`, `subscribe`, `diagnostics` and **`replaceAll(state)`**. Store `replaceAll`/`clearAll` call it **once**, so a bulk operation is one atomic `data.json` write and one notification. Without it, 2000 items meant 2000 full rewrites and 2000 reloads in every other leaf. Part 5's `allSettled` per-record loops and their partial-failure tests are replaced by atomic behaviour. Part 5 E18–E20 still hold: `bulkBusy`, the refusals, and staying bound to the starting codebase. | Medium. A failed import now changes nothing, where before it could leave a partial state. That is strictly better for the user, but the Part 5 tests that pinned partial state are rewritten, so a reviewer must check the rewrite keeps E18–E20. |
| U16 | A durable `replaceAll`/`clearAll` replaces the **whole** record set, including records that were skipped but kept. It is an explicit user replace or clear. Ordinary upserts and removes never touch skipped records (Y7). | Low. A user who clears review state also loses unreadable hand-edited records, which is what Clear means. |
| U17 | The durable adapter's `allocateId` **throws** before the adapter has absorbed the stored set. Every write also re-absorbs `highWater` and every raw id under the lock. The store's `ready` gate (adds refuse with `null` until the first load has finished) makes the throw unreachable from the UI. The in-memory adapter never throws. | Low. A future caller that allocates without loading gets a developer error, not a silently overwritten record. |
| U18 | Every durable `list*` re-reads `data.json`, sharing a read already in flight. This resolves Y8's "cache after first read" against Y19's "picked up on the next bind" in favour of Y19. Only the id marks and the diagnostics are cached. | Low. One `loadData` per `load()`. |
| U19 | `review-record-codec.ts` sits in `src/ui/read-models/` and reuses the Part 5 export and import helpers. The durable adapter imports it and the port from `src/ui/`. These are the first adapters → ui edges. No lint rule forbids them, and the port has lived in `src/ui/stores/ports` since Part 4. | Low. Moving the port and codec to the application layer later is a mechanical rename. |
| U20 | `encodeWorkItem`/`encodeDisposition` take `repositoryId` and refuse a file target or fingerprint that belongs to another repository, or that is not a file entity. | None. It prevents a silent re-homing of paths. |
| U21 | A purge retires the adapter instance (`retire()`): later writes reject `'unsupported'`, and its subscribers are notified once. A leaf still showing a removed profile therefore cannot recreate `reviews[id]`. `registry.for('')` returns an unpersisted in-memory repository. | Low. |
| U22 | `detach()` (review store) and `unwireDataPorts(pinia)` (`src/host/data-ports.ts`) are added. `CityView.onClose` calls `unwireDataPorts` before dropping the pinia. Nothing in the codebase ever calls `$dispose`, so without this a closed leaf's store would stay subscribed to the plugin-level repositories. | Low. Covered by a host test. |
| U23 | The evidence store and the lens store are Pinia **setup** stores; every other store is an options store. The evidence store uses setup so that `onScopeDispose` runs on `$dispose`. The lens store uses setup so that it can watch the evidence store with `flush: 'sync'`, which is load-bearing: the harness sets the lens right after `attach()`. | Low. |
| U24 | Store `loadFailed` is set when a load rejects, and Settings shows `REVIEW_STORE_READ_FAILED`.
